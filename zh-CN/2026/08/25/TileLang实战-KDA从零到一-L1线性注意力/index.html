TileLang 实战：KDA 从零到一（L1）--Chunked 线性注意力

发表于 2026-08-25 分类于 技术 Disqus：

TileLang 实战：KDA 从零到一（L1）–Chunked 线性注意力

KDA（Kimi Delta Attention）的递推式一行就写完，但直接照着它写 kernel 会同时撞上四件事：逐通道门控、delta rule 的三角求解、log 域 cumsum、跨 chunk 状态传递。把这四件事一次性塞进一个 kernel，调不通时无法定位是哪一层错了。 本文的做法是搭一个五级阶梯，每级只加一个新机制、每级都能独立运行并做数值验证；L1 是阶梯的第一级–去掉全部衰减因子和删除因子，只留 S←S+K⊤VS \leftarrow S + K^\top VS←S+K⊤V。

L1 的价值不在性能，在于它把 chunkwise 分解这个恒等式单独隔离出来验证。本文顺带给出一个反直觉的结论：L1 采用的"每块自食其力"策略会让 FLOPs 退回 O(N2)O(N^2)O(N2)，且与因果 FlashAttention 同量级–线性注意力的线性复杂度在这一级还没兑现。

数学背景见《KDA 的来龙去脉》，TileLang 语言基础见《TileLang 编程基本知识点》，本文复用的 tile 切分与 fragment 累加模式见《TileLang 实战：FlashAttention 前向 Kernel》。

1. 五级阶梯：把 KDA 拆成可验证的增量

KDA 的完整递推式（Dt=diag⁡(egt)D_t = \operatorname{diag}(e^{g_t})Dt​=diag(egt​)，gt∈R<0dkg_t \in \mathbb{R}^{d_k}_{<0}gt​∈R<0dk​​）：

St=St−1Dt(I−βtktkt⊤)+βtvtkt⊤,ot=StqtS_t = S_{t-1} D_t (I - \beta_t k_t k_t^\top) + \beta_t v_t k_t^\top, \qquad o_t = S_t q_t St​=St−1​Dt​(I−βt​kt​kt⊤​)+βt​vt​kt⊤​,ot​=St​qt​

把这个式子按机制拆解，每级只放开一个自由度：

级别 递推式 新增机制 新出现的实现结构
L1 S←S+K⊤VS \leftarrow S + K^\top VS←S+K⊤V – 分块恒等式本身、块内因果掩码
L2 S←γS+K⊤VS \leftarrow \gamma S + K^\top VS←γS+K⊤V 标量衰减 块内权重从 0/1 变 γi−j\gamma^{i-j}γi−j 指数下三角
L3 S←diag⁡(egt)⋅S+⋯S \leftarrow \operatorname{diag}(e^{g_t}) \cdot S + \cdotsS←diag(egt​)⋅S+⋯ 逐 token 门控 log 域 cumsum、exp2 硬件指令
L4 S←S(I−βkk⊤)+βvk⊤S \leftarrow S(I - \beta k k^\top) + \beta v k^\topS←S(I−βkk⊤)+βvk⊤ delta rule UT 变换、三角求解（wy_fast 雏形）
L5 门控 + delta rule 二者耦合 五阶段流水线、跨 kernel 状态传递

L5 才是完整 GDN / KDA，结构对标 flash-linear-attention 的 cumsum -> chunk_scaled_dot_kkt -> wy_fast -> chunk_delta_h -> chunk_o。

这样拆的收益是定位能力：L3 数值不对，可以确定问题在 log 域 cumsum 或 exp2 精度，与 delta rule 无关，因为 L4 还没引入。反过来如果一上来就写 L5，误差出现时 UT 变换的三角求解和逐通道衰减的爆炸问题会互相掩盖。

一句话总结：阶梯不是教学噪音，是把一个多机制耦合的 kernel 的调试搜索空间从乘法降成加法。

2. L1 的数学：分块恒等式

L1 的递推没有任何遗忘，状态只进不出：

St=St−1+ktvt⊤,ot=qt⊤StS_t = S_{t-1} + k_t v_t^\top, \qquad o_t = q_t^\top S_t St​=St−1​+kt​vt⊤​,ot​=qt⊤​St​

展开成显式求和，因果且包含当前 token：

oi=∑j≤iqi⊤(kjvj⊤)=∑j≤i(qi⋅kj) vjo_i = \sum_{j \le i} q_i^\top (k_j v_j^\top) = \sum_{j \le i} (q_i \cdot k_j)\, v_j oi​=j≤i∑​qi⊤​(kj​vj⊤​)=j≤i∑​(qi​⋅kj​)vj​

这就是标准线性注意力–和 softmax attention 的唯一区别是分数没过 softmax，所以求和顺序可以自由交换，这才有了下面的分块重写。

2.1 把求和劈成"跨块"与"块内"两段

序列按 BCBCBC 切成 NC=N/BCNC = N / BCNC=N/BC 个 chunk。对第 ccc 块内的第 iii 个 token，把 j≤ij \le ij≤i 的求和范围劈成两半–落在更早的完整块里的，和落在当前块里的：

关键在第一项：括号里的量对整个 chunk ccc 是同一个矩阵，记作 Scbefore=∑c′<cKc′⊤Vc′S_c^{\text{before}} = \sum_{c' < c} K_{c'}^\top V_{c'}Scbefore​=∑c′<c​Kc′⊤​Vc′​，形状 dk×dvd_k \times d_vdk​×dv​。于是跨块贡献退化成一次矩阵乘 QcScbeforeQ_c S_c^{\text{before}}Qc​Scbefore​，块内贡献是一个 BC×BCBC \times BCBC×BC 的下三角掩码矩阵乘：

这条恒等式是整个阶梯的地基，L2 到 L5 都是在它的两项上分别插入衰减权重，形状与 GEMM 的调用次序完全不变。

3.1 一个必须踩的 einsum 坑

第一版写的是 torch.einsum("bhcnd,bhcnv->bhcdv", ...)；如果误写成 ->bhcdd（想表达"输出是 d×dd \times dd×d 方阵"），会直接抛异常：

einsum 的输出下标不允许重复–重复下标在输出侧的语义是取对角线，而 K^T V 的两个维度虽然长度都是 DDD，语义上分别是 key 维和 value 维，必须用不同字母 d 和 v。同理 bhcnd,bhcdd->bhcnv 也不合法（输出的 v 从未在输入中出现）。dk=dvd_k = d_vdk​=dv​ 时长度相同掩盖了语义差别，一旦 KDA 里 dk≠dvd_k \ne d_vdk​=dv​，这个疏忽会立刻变成形状错误。

4. TileLang kernel：三步走

grid 划分与 FA 完全一致–按 Q 块切分所有权，每个 block 负责输出一个 BC×dBC \times dBC×d 的 tile：

4.1 步骤①：流式累加出本块开拍时的状态

T.Pipelined(bx) 的上界是 block 索引，不是编译期常量–这意味着不同 block 的循环次数不同，第 0 块一次都不执行（S=0S = 0S=0），最后一块要跑 NC−1NC-1NC−1 次。TileLang 支持 runtime 上界的流水线，但代价是各 block 负载严重不均衡，尾部 block 成为整个 kernel 的关键路径。

这一步叫每块自食其力：第 bxbxbx 块不依赖任何别的 block 传给它状态，自己从头累加一遍。好处是单 kernel 闭环、零跨 block 同步；代价见 §6。

4.2 步骤②③：两项贡献相加

步骤③开头必须重新 T.copy 当前块的 K/V。原因是步骤①的流水线循环结束时，K_s / V_s 里残留的是第 bx−1bx-1bx−1 块的数据，而且在 num_stages > 1 下究竟残留哪一块取决于流水线的展开方式，不能假设。复用 shared buffer 省了显存，但必须显式重载，这是 tile 编程里典型的隐式状态陷阱。

T.copy(A, A_cast) 这次 f32→f16 转换与 FA 里 P~\tilde{P}P~ 喂第二个 GEMM 前的降精度是同一个操作–Tensor Core 的 MMA 输入必须是低精度，累加器才是 f32。

5. 与 FlashAttention 的三点结构差异

L1 复用了 FA 的全部 tile 模式，但有三处必须改：

维度 FlashAttention L1 线性注意力 原因
归一化 online softmax，维护 mmm、ℓ\ellℓ 两个行状态，每块重标定 无，掩码直接置 0 没有 exp，求和顺序可交换
循环携带的量 无跨块状态，每个 Q 块独立 S[dk,dv]S[d_k, d_v]S[dk​,dv​] 是跨迭代累加的记忆 递推式本身带状态
T.gemm policy 必须 FullRow–行归约要求整行在同一 warp 默认 Square 即可 无按行归约

第三点值得展开：FA 需要对分数块做 rowmax / rowsum，如果一行被切分到多个 warp，归约就要跨 warp 通信，所以必须用 FullRow policy 强制一行不拆。L1 的块内矩阵 AAA 算完只做 elementwise 掩码，没有任何跨列归约，warp 怎么切都不影响正确性，编译器可以自由选择寄存器分布最优的方案。

第二点是从 L1 走向 L5 的主线矛盾。L1 用"每块自食其力"把状态依赖藏起来了，但 L5 的 chunk_delta_h 必须真正在 chunk 之间传递状态–那时状态要在 fragment（累加）与 shared（作为下一个 GEMM 输入）之间每轮拷贝一次，并且需要拆成两个 kernel 协作。

6. 代价账本：O(N2)O(N^2)O(N2) 还在，线性复杂度尚未兑现

"每块自食其力"的冗余是可以精确算出来的。第 bxbxbx 块执行 bxbxbx 次 K⊤VK^\top VK⊤V，全部 block 合计 ∑c=0NC−1c=NC(NC−1)/2\sum_{c=0}^{NC-1} c = NC(NC-1)/2∑c=0NC−1​c=NC(NC−1)/2 次，而理想情况每块只需算一次，共 NCNCNC 次。冗余系数就是 (NC−1)/2(NC-1)/2(NC−1)/2。

单次 K⊤VK^\top VK⊤V 的 FLOPs 是 2⋅BC⋅dk⋅dv2 \cdot BC \cdot d_k \cdot d_v2⋅BC⋅dk​⋅dv​，取 dk=dv=Dd_k = d_v = Ddk​=dv​=D，步骤①的总量：

FLOPs①=NC(NC−1)2⋅2 BC D2≈N2D2BC\text{FLOPs}_① = \frac{NC(NC-1)}{2} \cdot 2\, BC\, D^2 \approx \frac{N^2 D^2}{BC} FLOPs①​=2NC(NC−1)​⋅2BCD2≈BCN2D2​

对比因果注意力的 2N2D2N^2 D2N2D（两个 GEMM 各占一半三角），比值是：

FLOPs①FLOPscausal FA=D2 BC\frac{\text{FLOPs}_①}{\text{FLOPs}_{\text{causal FA}}} = \frac{D}{2\,BC} FLOPscausal FA​FLOPs①​​=2BCD​

这个比值与 NNN 无关–也就是说 L1 的计算量和因果 FlashAttention 是同一个量级，只差一个由 D/BCD / BCD/BC 决定的常数。实测账本（D=64D = 64D=64，BC=64BC = 64BC=64）：

BCBCBC 的取舍随之清晰：

BCBCBC D/(2BC)D/(2BC)D/(2BC) 含义

调大 BCBCBC 能线性减少冗余，但 AAA 是 BC×BCBC \times BCBC×BC 的 f32 fragment，BC=128BC = 128BC=128 时寄存器压力已经接近溢出边界。真正的解法不是调 BCBCBC，而是换掉"每块自食其力"–用两个 kernel 协作，第一个 kernel 算出所有 chunk 的前缀状态写回 HBM，第二个 kernel 读取。这正是 L5 chunk_delta_h 的结构，也是为什么官方实现要拆五个 kernel 而不是一个。

一句话总结：L1 用 (NC−1)/2(NC-1)/2(NC−1)/2 倍的冗余计算换来单 kernel 闭环和零跨 block 同步，这个交易在教学上成立、在生产上不成立–它把线性注意力的核心优势整个交易掉了。

7. 数值验证

三层验证的组织方式：

  1. 参考 A vs 参考 B（均 fp64）：验证 §2.1 分块恒等式的正确性，与 GPU 无关，误差应在 10−1510^{-15}10−15 量级；
  2. kernel vs 参考 A：验证 TileLang 实现，fp16 输入 + f32 累加，阈值取相对 L2 <2×10−2< 2 \times 10^{-2}<2×10−2；
  3. 延迟对比走 CUDA event 中位数，取 50 次采样。

第 2 层阈值定在 2×10−22 \times 10^{-2}2×10−2 而不是更严，是因为 T.copy(S_f, S_s) 把 f32 状态降到 f16 落 shared。这个降精度是必要的–Tensor Core MMA 的输入必须是低精度–但状态 SSS 是 NCNCNC 个块累加的结果，越靠后的 block 累加项越多，误差随 bxbxbx 单调增长。这是 L1 精度的主导误差源，比块内那次 AAA 的降精度影响大得多。

第 1 层验证已在 numpy fp64 上完成（见 §3 表格，相对 L2 1.12×10−161.12 \times 10^{-16}1.12×10−16）。第 2、3 层需要 CUDA 设备，本文未给出实测数字–待真卡跑通后单独补一篇实测数据，此处不做性能推测。

8. 总结

  1. L1 剥掉了 KDA 的全部衰减因子与删除因子，只留 S←S+K⊤VS \leftarrow S + K^\top VS←S+K⊤V，目的是把 chunkwise 分解恒等式 Oc=QcScbefore+tril⁡(QcKc⊤)VcO_c = Q_c S_c^{\text{before}} + \operatorname{tril}(Q_c K_c^\top) V_cOc​=Qc​Scbefore​+tril(Qc​Kc⊤​)Vc​ 单独隔离验证。这条恒等式是 L2 到 L5 的公共地基，后续每级只在它的两项上插入衰减权重，GEMM 的形状与次序不变。
  2. 与 FA 的差异集中在三点：无 online softmax（掩码置 0 而非 −∞-\infty−∞）、循环携带 dk×dvd_k \times d_vdk​×dv​ 状态、无按行归约（T.gemm policy 用默认 Square 即可）。
  3. 实测数字：两份 fp64 参考的相对 L2 误差 1.12×10−161.12 \times 10^{-16}1.12×10−16，恒等式无误。但代价账本显示 N=16384N = 16384N=16384 时"每块自食其力"的冗余系数达 127.5 倍，步骤① FLOPs 是因果 FlashAttention 的 0.498 倍，且该比值 D/(2BC)D/(2BC)D/(2BC) 与 NNN 无关–线性复杂度在 L1 尚未兑现。
  4. 两个实现陷阱：einsum 输出下标不可重复（->bhcdd 会抛异常，key 维与 value 维必须用不同字母）；T.Pipelined 之后 shared buffer 残留内容取决于流水线展开方式，复用前必须显式重载。

下一步 L2 加入标量衰减 S←γS+K⊤VS \leftarrow \gamma S + K^\top VS←γS+K⊤V。改动集中在块内那项–下三角掩码从 0/1 矩阵变成 γi−j\gamma^{i-j}γi−j 的指数权重，跨块那项则要给 SSS 乘上整块的衰减 γBC\gamma^{BC}γBC。γ\gammaγ 一旦从标量升级成逐通道向量（L3），指数外提就会引入 1/Γ1/\Gamma1/Γ 的数值爆炸，那是这个阶梯上第一个真正棘手的问题。

可迁移的启示：多机制耦合的 kernel 不要一次写完。每级只放开一个自由度，并且每级都留一份可独立运行的 fp64 参考–参考实现的成本远低于在五个机制里定位一个误差源的成本。
